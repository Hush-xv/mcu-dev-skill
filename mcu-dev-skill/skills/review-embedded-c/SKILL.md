# 嵌入式 C 通用质量评审

适用于 MCU 固件中的 C 代码。先按本清单检查语言与控制流风险，再加载对应的 `review-arm-cortex-m`、`review-riscv` 或 `review-mcs51` 检查芯片、ABI、编译器和外设细节。这里的通用检查不替代手册、编译器文档或架构清单。

## 工作方式

- 先追踪被检查逻辑的输入、状态变化、调用方和错误返回路径；修 bug 时找共享根因，不只看报告点名的一行。
- 只报告可由源码、构建配置、编译器输出或硬件文档支持的问题。区分已证实问题与待验证风险，并给出验证动作。
- 评审请求只输出发现，不擅自改代码。修改请求遵循项目工作流，给出最小 diff，并验证可用的构建或检查命令。
- 先识别语言标准、编译器、目标 ABI 和整数宽度。8051、厂商扩展、`sbit`/`sfr`、地址空间限定符等按实际工具链语义判断；不能用桌面 GCC 的假设代替目标编译器。
- MISRA、CERT C、Linux 或 FreeRTOS 规则只有在项目声明采用时才作为合规标准；否则把它们当作参考，不宣称符合标准。

## 检查清单

### 1. 输入、边界与整数

- [ ] 外部数据、长度、索引、命令码和枚举值在使用前经过范围检查；校验发生在数组访问和指针运算之前。
- [ ] 加减乘除、移位、窄化转换、符号转换和有符号/无符号比较不会溢出或改变含义；长度计算不会在分配、复制或循环前回绕。
- [ ] 移位宽度有效；常量类型、整型提升和目标 `int` 宽度与预期一致。
- [ ] 定时器回绕比较、计数器溢出和饱和策略符合目标类型与时间范围。

### 2. 指针、数组与对象生命周期

- [ ] 指针可空性、缓冲区容量、对齐、对象生命周期和所有权清楚；复制/格式化长度包含终止符需求。
- [ ] 返回局部对象地址、重复释放、悬空指针、越界访问、未初始化读取和不匹配的读写长度均已排除。
- [ ] `memcpy`/`memmove`/`memset` 的长度与目标对象大小匹配；重叠场景使用正确函数。

### 3. 状态、错误与资源

- [ ] 每个函数的输入约束、状态更新和失败行为明确；失败不会留下半更新状态或被静默忽略。
- [ ] 返回值、状态位和硬件错误标志被检查或有明确理由忽略；超时和重试有上限。
- [ ] 深层调用、递归、局部数组、格式化输出和中断嵌套的栈占用适合目标 RAM；动态分配有失败处理和可解释的生命周期。
- [ ] 表驱动状态机检查非法状态与非法迁移；默认分支不会把未知输入误当成功。

### 4. 并发、ISR 与 RTOS

- [ ] 共享状态的所有读写路径都已识别；按目标编译器/ABI 判断异步可观察访问是否需要 `volatile`，不能把它当作原子性、任务间同步、互斥、临界区或内存顺序保证。
- [ ] 多字节访问、读改写、位域和复合状态在 ISR/任务或多核间不会撕裂；同步方式与目标编译器及 MCU 能力相符。
- [ ] ISR 保持短小、非阻塞；不在 ISR 中做无界轮询、长延时、不可重入调用或不允许的日志/分配操作。
- [ ] RTOS API 的任务/ISR 变体、调用优先级约束、对象生命周期和阻塞语义符合所用 RTOS 与端口文档。

### 5. 可维护性与工具证据

- [ ] 类型、常量和接口表达实际范围与单位；位掩码和寄存器操作不会因隐式转换或读改写副作用破坏其他位。
- [ ] 条件、循环和状态更新易于审查；注释解释硬件约束或非显然原因，不重复代码字面含义。
- [ ] 按用户授权和 `embedded-workflow` 任务模式执行项目已有构建、编译器告警、静态分析或测试；未要求验证且工作流未要求时，不自动运行测试。工具不可用时说明未验证项，不臆造通过结果。
- [ ] 日志仅放在适合的路径，避免 ISR、时序敏感或高频路径中的阻塞输出和显著时序扰动。

## 发现报告格式

按严重度列出发现：

`[严重度] 文件:行号 — 具体问题；触发条件与后果；最小修复建议；证据/验证方式`

按 `embedded-workflow` 的统一严重度定义定级：Critical 用于明确的安全/硬件损坏、严重数据破坏或不可恢复失效；High 用于已说明条件下的功能错误、失控或系统不稳定；Medium 用于有具体后果的较低风险或维护性问题。无发现时说明检查范围、未覆盖项和实际运行过的验证命令。不要把风格偏好包装成缺陷，也不要声称仅靠 AI 评审即可证明 MISRA/CERT 合规。
