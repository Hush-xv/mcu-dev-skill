# 通用 MCU 固件开发工作流

三条铁律（凌驾于一切效率考量之上）：

1. **环境先行** — 文件能探测到的信息绝不问用户；探测不到的结构化提问；任何信息不靠猜。
2. **手册为源** — 寄存器值、引脚复用、电气参数以用户提供的 PDF 手册为准；每条摘录必须带文档名+页码，可追溯。
3. **门禁构建** — 缺文件不代造、缺工具给安装指令、板子不在线不烧录；每道门未过就 STOP。

## 五阶段流水线

按序执行，每阶段产出是下一阶段的显式输入，禁止跳阶段、禁止并行合并。

### 阶段 1：环境分析（只读 + 提问，不写任何代码）

先扫描项目文件自动探测，再补问缺口：

| 探测目标 | 文件特征 |
|---|---|
| CubeMX / MounRiver 工程 | `*.ioc`、`*.mxproject` |
| 构建系统 | `Makefile`、`CMakeLists.txt`、`platformio.ini` |
| 商业 IDE | `*.uvprojx`(Keil)、`*.ewp`(IAR)、`.cproject`(CubeIDE) |
| MCU 型号 | 启动文件名（`startup_stm32*` / `startup_ch32v*` / `STARTUP.A51`）、链接脚本、设备头文件 |
| 开发方式 | 库 API 调用（`HAL_*` / `LL_*` / WCH `*_Periph`）/ 裸机寄存器直访 / 两者混合 |
| RTOS | `FreeRTOSConfig.h`、`cmsis_os2.h`、`tx_api.h` |
| 可用手册 | `docs/` 目录（见阶段 2 约定） |

探测前先查板级档案：Glob `docs/board-*.md`——存在则通读（按 `board-profile` skill），以其事实表与规则表为开局基准；档案与扫描结果冲突时，以档案中标注"硬件实测"的记录为准并向用户确认。

探测不到的关键信息（目标型号、工具链、外设需求、晶振频率）用结构化提问补齐。

输出 **Environment Profile**：

```markdown
## MCU 环境档案
**目标型号**: [完整型号，如 STM32F407VGT6 / CH32V203C8T6 / STC8H1K08]
**内核/架构**: [Cortex-M4 / RV32IMAC / 8051(1T)]
**主频上限 / 实际主频**: [xxx MHz]
**Flash / RAM**: [容量与布局]
**开发方式**: [厂商库 / 裸机 / 混合]
**工具链**: [编译器+版本, 构建系统]
**RTOS**: [名称+版本 / 无]
**外设清单**: [外设 → 中断/DMA/轮询 → 用途]
**时钟配置**: [晶振、锁相环、各级总线频率]
**可用文档**: [逐类列出文件名或"缺失"]
**项目结构**: [源码/头文件/链接脚本/启动文件路径]
```

### 阶段 2：手册精读（只读）

手册目录约定（对任何厂商通用，放用户项目根下）：

```text
docs/
├── reference-manual/     # 参考手册：寄存器位域、外设章节、配置时序（最常用）
├── datasheet/            # 数据手册：引脚定义、复用表、电气参数、封装
├── user-manual/          # 用户手册：板级布局、晶振频率、跳线、外设接线
├── programming-manual/   # 编程手册：内核指令、调试接口（Cortex-M / RISC-V）
├── application-notes/    # 应用笔记：实践指南、参考代码
├── technical-notes/      # 技术笔记
└── security-docs/        # 安全公告与加固指南
```

PDF 精读策略：
1. 先读目录（前 1~5 页）定位章节页码
2. 按 15~20 页为单位精读目标章节
3. 跨文档交叉引用（如：数据手册查复用表 + 参考手册查寄存器配置）

纪律：
- 每条摘录标注文档名与页码
- 完整表（内存映射、DMA 请求映射、复用表）完整提取，不摘要
- 找不到的信息明确说 "not found"，并指出需要哪类文档、去哪下载（见工具链矩阵表下方）
- 文档版本/型号差异要显式标注

输出 **Documentation Extraction**（含 Source[文档/章节/页码]、寄存器表[偏移/位域/R-W/复位值]、配置步骤序列、交叉引用）。

### 阶段 3：编码（生产级纪律，架构无关）

- 所有硬件寄存器访问与 ISR 共享变量加 `volatile`
- 初始化顺序模板：**时钟使能 → 引脚配置 → 外设寄存器 → 中断控制器 → DMA → 外设使能（最后一步）**——时钟未开就访问寄存器在任何架构上都是总线错误
- ISR 最小化：清标志、短处理、耗时工作移交主循环/任务；硬件轮询必带超时退出
- 禁止 magic number，一律用厂商头文件宏定义
- 生成完整可编译文件（含全部 include 与原型），不是片段
- 错误处理用返回码，禁止静默失败
- 手册在手时寄存器值以手册为准，注释引用手册章节页码
- 提交前心测编译：include 完整、无未声明变量、类型匹配

### 阶段 4：硬件评审（加载对应架构清单）

按阶段 1 探测到的架构加载专项清单：

- **ARM Cortex-M**（STM32/GD32/NRF/RP2040 等）→ `review-arm-cortex-m`
- **RISC-V**（CH32V/GD32V/ESP32-C 系等）→ `review-riscv`
- **8051**（STC8/STC15/N76 等经典与增强 51）→ `review-mcs51`

路由规则：代码评审/生成后检查 → 按架构清单逐类核查；排障任务（症状已知）→ 直接查对应清单的"症状→原因→修法"表归因，命中后再精读相关类别；症状跨架构或表内未命中 → 回阶段 1 重新分析。

评审规范：
- 分级报告：Critical（必挂）/ High（大概率 bug）/ Medium（坏习惯）
- 每条含 `文件:行号` + 问题 + 后果 + 修法
- 置信度 <75% 的项标 "待手册核对"，不报为确定问题
- 报告后**重新生成应用了全部修复的完整代码**（drop-in 可替换），不许只列清单

### 阶段 5：构建门禁（检查 + 放行，不代造）

三道门，逐道过，未过即 STOP 并输出可执行的下一步指令：

**门 1 — 项目文件完备性**：启动文件、链接脚本、系统初始化、设备头文件、main。
缺任一项：列出缺失清单 + 说明该文件作用 + 指引用厂商工具生成（CubeMX/MounRiver/STC-ISP 工程、厂商 SDK），**绝不自己代造这些文件**，然后停止。

**门 2 — 工具链与烧录链**（见下方矩阵）：逐个检查命令可用性，缺任一项：给出 per-OS 安装命令，然后停止。

**门 3 — 目标板在线**：按矩阵检测 USB VID 或串口；未检测到：给出排障步骤（线缆/驱动/Boot 模式/udev 规则），然后停止。

三道门全过 → 生成构建 Makefile：
- 源文件列表、包含路径、链接脚本、启动文件全部来自**实际探测结果**，禁止通配符占位
- 目标：`make`（编译）、`make flash`（编译+烧录，先复验板子在线）、`make clean`、`make disasm`
- 显式标注需要用户核对的两行：烧录器配置与目标芯片配置

档案钩子：该板首次 bring-up 成功即按 `board-profile` skill 建初版档案；排障修复后立即追加症状行。

## 表达与报告纪律（全阶段适用）

- 祈使句；完整引脚/寄存器名，禁止"相应 GPIO"式含糊表述。
- 事实用表格、机制用散文、代码只在字节级精确处出现。
- 每条结论必带后果，无后果的删；通用知识已覆盖的不复述。
- 各阶段产出末尾附**验证状态**：硬件实测 / 手册推导（文档名+页码）/ 未验证推断，逐项标注。
- 不写 TODO、不道歉；没验证就写"未验证"并继续。

## 工具链与烧录矩阵

| 架构 | 编译器 | 烧录/调试 | 板载检测 |
|---|---|---|---|
| ARM Cortex-M | `arm-none-eabi-gcc` | OpenOCD / pyOCD / J-Link | USB VID `0x0483`(ST) / `0x1366`(Segger) / `0x2e3a`(CMSIS-DAP) |
| RISC-V (WCH CH32V) | `riscv-none-elf-gcc`(xPack) 或 MounRiver 自带 GCC | OpenOCD-WCH / minichlink / WCH-LinkUtility | USB VID `0x1a86`(WCH-Link/CH34x) |
| RISC-V (ESP32-C3/C6) | ESP-IDF (`riscv32-esp-elf-gcc`) | `esptool` / `idf.py flash` | USB VID `0x303a`(Espressif) |
| 8051 (STC 等) | SDCC 或 Keil C51 | `stcgal` / 官方 STC-ISP（串口冷启动 ISP） | USB 转串口 VID `0x1a86`(CH340) |

手册下载渠道：ST.com（RM/DS/UM/AN 全套）、WCH（wch.cn + MounRiver 文档）、Espressif（espressif.com/docs）、STC（stcmcudata.com，中文）。

## 手册缺失时的降级策略

用户暂无 PDF 时：明确告知需要哪类文档；基于通用知识编码时，所有寄存器值与复用配置逐项标注 **"未经该型号手册核对，烧录前需核对"**，并建议尽快补 `docs/`。
