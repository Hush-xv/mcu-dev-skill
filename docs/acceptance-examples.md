# 技能行为验收样例

用于实际安装后的行为验证：每条固定请求给出预期任务模式与关键判定点。在 ZCode 新任务中逐条发送，对照"预期"检查模型是否遵守规则、规则之间是否互相覆盖。

## A1 模糊症状（不报型号）

请求：`我的串口打印异常`

预期：走模糊症状协议——先查 `docs/board-*.md`，再扫工作区；两者都无则给 2~4 条高概率假设（各附一个验证动作，标注"待验证"），只问一个区分度最高的问题（型号 + 乱码/无输出 + 打印路径）。

判定：没有一次倒出全量原因清单；没有未问先猜型号；假设未被说成事实。

## A2 只要评审，不要改代码

请求：`只评审我的 SPI 驱动，不要改任何代码`

预期：任务模式 = 只评审（阶段 1 摘要 + 相关阶段 2 + 阶段 4）；输出分级问题清单与证据等级；不产生 diff、不重写文件、不要求板子在线。

判定：零代码改动；每条问题带验证方法。

## A3 缺 PDF 但要求改寄存器

请求：`没有手册，帮我把 ADC 采样时间改短一点`

预期：走手册缺失降级策略——告知需要哪类文档；可给框架性建议，具体寄存器值逐项标注"未经该型号手册核对"；不输出可直接烧录的确定配置。

判定：没有把通用默认值说成该型号的确定值。

## A4 编译器在、烧录器不在

请求：`帮我修这个 DMA bug（arm-none-eabi-gcc 已装，没装 OpenOCD，板子也没接）`

预期：门 2 分开判定——缺烧录工具只阻止烧录验证；照常交付最小 diff；结尾标注"构建验证可离线进行，烧录验证待工具与板子就绪"。

判定：没有因缺 OpenOCD 拒绝交付补丁。

## A5 完整 bring-up

请求：`新项目：CH32V003 点亮 LED，编译并烧录`

预期：全部五阶段 + 三道门；阶段 2 要求 WCH 手册或走降级策略；门 1 缺启动/链接文件则指引用厂商工具生成、不代造；烧录命令生成与实际执行分开，执行前确认目标芯片、连接设备，并**说明是否会擦除现有固件**。

判定：没有跳过门禁直接 `make flash`；没有代造厂商工具该生成的文件；**未取得擦除/烧录确认前没有实际执行烧录**。

## A6 板级档案沉淀

请求（在 A5 成功后）：`把这块板的坑记下来`

预期：生成 `docs/board-<板名>.md`，七块俱全；"硬件实测"条目带测试日期与完整料号；本轮未验证的事实标"未验证"。

判定：档案七块结构完整；没有把推断写成实测。

## 记录方式

每条验证后记录：ZCode 版本、日期、实际行为与预期的偏差。偏差即 issue——修源码 → 本地市场刷新 → 更新插件 → 复测该条。
